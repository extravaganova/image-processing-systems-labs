# Лабораторная работа №2

**Дисциплина:** системы компьютерной обработки изображений  
**Тема:** трекинг объекта на видео по ключевым точкам  
**Выполнила:** Ваганова Мария Александровна

## 1. Теоретическая база

Ключевая точка — локально отличимый участок изображения: угол, пересечение линий или фрагмент текстуры. В работе используется ORB (Oriented FAST and Rotated BRIEF): FAST находит точки, а BRIEF формирует компактный бинарный дескриптор, устойчивый к повороту.

Для сопоставления применяется расстояние Хэмминга и тест отношения Лоу: совпадение принимается, если расстояние до ближайшего дескриптора заметно меньше расстояния до второго ближайшего. По хорошим парам точек вычисляется матрица гомографии `H` методом RANSAC. Она переводит четыре угла объекта из первого кадра в текущий кадр:

`p_current ~ H · p_reference`.

Так рамка учитывает перенос, масштаб, поворот и перспективное искажение плоского объекта.

## 2. Описание разработанной системы

Основной файл — `track_object.py`.

1. Из первого кадра берётся ROI объекта. Если ROI не передан, используется весь первый кадр.
2. На ROI вычисляются ORB-ключевые точки и дескрипторы.
3. На каждом следующем кадре снова ищутся ORB-точки.
4. BFMatcher с расстоянием Хэмминга и ratio test отбрасывает слабые совпадения.
5. RANSAC строит гомографию. При достаточном числе инлайеров рисуется зелёный четырёхугольник с подписью `Object: tracked`; иначе появляется красный статус `Object: not found`.

Архитектура:

```text
первый кадр + ROI -> ORB-дескрипторы -> BFMatcher -> RANSAC/H -> рамка объекта
                                                        |
                                                annotated video
```

## 3. Запуск

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Запуск на видео, где объект занимает первый кадр:

```bash
python track_object.py input.mp4 tracked.mp4
```

Если объект занимает только часть первого кадра, передайте прямоугольник `x,y,width,height`:

```bash
python track_object.py input.mp4 tracked.mp4 --roi 245,100,470,310
```

Параметры ROI отсчитываются от левого верхнего угла кадра. Результат сохраняется в `tracked.mp4`.

## 4. Результаты и тестирование

Для воспроизводимой проверки добавлен генератор `generate_demo.py`. Он создаёт синтетическое видео с текстурированной карточкой, движущейся с перспективным искажением:

```bash
python generate_demo.py
python track_object.py demo_input.mp4 demo_tracked.mp4 --roi 235,90,490,330
```

В отчётном эксперименте предусмотрены три варианта тестовых видео из задания:

| Видео | Проверяемое изменение | Ожидаемый результат |
|---|---|---|
| `test_translation.mp4` | перенос объекта | рамка следует за объектом |
| `test_rotation.mp4` | поворот и изменение масштаба | рамка меняет угол и размер |
| `test_perspective.mp4` | наклон плоского объекта | рамка становится четырёхугольником |

Для каждого ролика команда запускается одинаково; меняются только входной файл и ROI первого кадра. `demo_input.mp4` является самостоятельным воспроизводимым тестовым видео, подготовленным для этой работы. На кадрах, где объект виден, алгоритм рисует зелёную рамку; при недостатке соответствий корректно сообщает о потере объекта.

## 5. Выводы

ORB + BFMatcher + RANSAC подходят для трекинга текстурированного плоского объекта в условиях переноса, поворота и перспективы. Гомография даёт более точную рамку, чем обычный осевой прямоугольник. Качество зависит от количества текстуры, освещения, перекрытий и резкости кадров: на однотонном объекте ключевых точек недостаточно.
